# ARGUS results

The current evaluation is a small demonstration of evidence investigation, not a predictive-accuracy benchmark. The [architecture figure](../docs/figures/ARGUS_architecture.png) summarizes illustrated FOXA1 and KLF6 trajectories starting from precomputed DVR predictions. It does not establish end-to-end integration from one natural-language prompt or general predictive performance.

The KLF6 interpretation is: **Motif evidence opposes DVR; regulatory context is non-resolving.** Its abstention must not be presented as experimental confirmation or refutation of KLF6 binding. In the FOXA1 illustration, the evidence contradicts the DVR prediction while the investigation status is `rescued`.

## Local run artifacts

Generated outputs remain local. Everything under this directory except this README is ignored by default; raw run outputs are not included.

Retain enough local information to connect the report to inputs and evidence:

- Code revision, configuration, model identifiers, and resource versions.
- Variant/TF identity, assembly, coordinate convention, and preprocessing.
- DVR reference/alternate probabilities and whether they were supplied/precomputed or generated by a separately executed prediction stage.
- Planner policy, selected evidence actions, and observation provenance.
- Deterministic evidence states, final investigation status, and stopping/abstention reason.
- Fixed structured facts supplied to the reporter and its prose output.
- Anthropic model/settings for planning and reporting separately where used, without credentials.

Keep evidence-call counts separate from logged-event counts. Preserve unavailable, underpowered, contextual-only, and mixed evidence cases and their abstentions. Strong terminal decisions require admissible direct experimental evidence; computational motif evidence and regulatory context do not independently establish TF binding.

Label AlphaGenome Atlas outputs as a separate computational comparison. They are outside the loop and do not determine its verdicts.

## Sharing summaries

Only intentionally reviewed, small, sanitized summaries should be added to version control. Add a narrow `.gitignore` exception for each approved artifact. Exclude API keys, weights, knowledgebase databases, large result files, and user-specific server paths.

Describe the sample and what was actually executed. Do not extrapolate the demonstration to predictive accuracy, autonomous discovery, or clinical use.
